# Prophecy Multi-Verse API

A Fastify/TypeScript backend for a catalog and **legal playback-source** service. Metadata can be discovered for commercial titles even when no authorized playable media exists. The API never fabricates a URL, bypasses access controls, or treats a working URL as proof of legal rights.

## Architecture

The frontend calls Fastify routes. Catalog metadata and normalized source records are stored in local JSON for development or Firestore in production. Metadata providers discover titles; playback providers expose public/open media; a rights gate, URL/media normalization, source validation, priority ranking, and TTL cache sit between providers and player-ready responses.

Playback is cache-first. A valid cached source is ranked and returned immediately. On a miss or expired source, eligible providers are queried with bounded requests using `Promise.allSettled`, successful records are normalized and cached, and the best legal source is returned. An in-memory request map deduplicates concurrent resolution for the same title within one Render instance.

## Setup

```bash
cp .env.example .env
pnpm install
pnpm run typecheck
pnpm run build
pnpm run dev
```

Set `STORAGE_MODE=firestore` only when `FIREBASE_SERVICE_ACCOUNT_JSON` is available at runtime. The credential is never committed or logged. Firestore uses `/titles/{titleId}` for catalog documents and `/users/{uid}` for user data; no destructive migration is required. Local development uses `LOCAL_STORE_FILE`.

Important settings are `PROVIDER_TIMEOUT_MS` and `CACHE_TTL_SECONDS`. Every cached title/source includes `createdAt`, `updatedAt`, and `expiresAt` where it is generated by the sync layer.

## Providers

The registry preserves this exact priority order: PeerTube, Internet Archive, Wikimedia Commons, NASA SVS, Library of Congress, DVIDS, NOAA, USGS, U.S. National Archives, and Prelinger Archives.

| PeerTube | Yes | Yes | Yes | Yes | Yes | N/A | License label required | Real instance API check |
| Internet Archive | Yes | Yes | Yes | N/A | Yes | Yes | Item metadata required | Real metadata check |
| Wikimedia Commons | Yes | Yes | Yes | N/A | Yes | Yes | Item extmetadata required | Real API check |
| NASA SVS | Yes | Yes | Yes | N/A | Yes | Yes | NASA public-domain policy and item notes | Real SVS API check |
| Library of Congress | Yes | Yes | Yes where item resources expose video | N/A | Yes | Yes | Item rights required | Real LOC API check |
| DVIDS | N/A | N/A | N/A | N/A | N/A | N/A | N/A | `not_implemented` |
| NOAA | N/A | N/A | N/A | N/A | N/A | N/A | N/A | `not_implemented` |
| USGS | N/A | N/A | N/A | N/A | N/A | N/A | N/A | `not_implemented` |
| U.S. National Archives | N/A | N/A | N/A | N/A | N/A | N/A | N/A | `not_implemented` |
| Prelinger Archives | Archive-derived | Archive-derived | Archive-derived | N/A | Yes | Yes | Item metadata required | Real Archive check |

`N/A` is intentional where the provider does not expose that format or the adapter does not claim it. DVIDS, NOAA, USGS, and the U.S. National Archives remain `not_implemented` because this project does not have a stable, unauthenticated, documented public media API configuration for them; their status is not represented as healthy. PeerTube uses the documented public REST API on a public instance and rejects private, restricted, non-local, and unknown-rights videos. NASA SVS uses its documented search API and public-domain media policy. Internet Archive, Wikimedia, Library of Congress, NASA SVS, and PeerTube return sources only after rights and format checks. Prelinger is handled as an Archive-derived adapter and must still pass item-specific rights checks.

## API

Public routes include `GET /health`, `GET /ready`, `GET /api/search?q=...`, `GET /api/titles/:id`, `/seasons`, `/episodes`, `/sources`, and `/playback`, `GET /api/episodes/:id`, `/playback`, `GET /api/providers`, and `GET /api/providers/:id/health`. `/api/v1` aliases remain available for search, catalog, playback, and provider routes.

Playback success has `success: true`, `available: true`, and a `playback` object with `type`, `url`, `mimeType`, quality/resolution, language fields, subtitles, duration, provider, source ID, and rights evidence. When no legal playable source exists, the API returns `success: true`, `available: false`, and `playback: null`.

Protected user routes are `GET` and `PUT /api/user/profile`, `/favorites`, `/history`, and `/settings` as applicable. They require `Authorization: Bearer <Firebase ID token>`. The server verifies the token with Firebase Admin and uses only the verified UID for `/users/{uid}` access. No client-supplied UID is trusted.

## Legal policy and source validation

Acceptable rights statuses are `public-domain`, `open-license`, and `authorized`. Unknown, restricted, private, authentication-required, paywalled, and DRM-only sources are rejected. URLs must be HTTPS provider URLs or provider-generated direct media URLs, and only HLS, MP4, and WebM are normalized. Provider timeouts prevent an external service from hanging a request. The frontend owns the video player; the backend only returns validated player-ready source metadata.

## Render deployment

Use the existing commands:

```text
Build: pnpm install --frozen-lockfile && pnpm run build
Start: pnpm run start
```

Configure `PORT`, `STORAGE_MODE=firestore`, Firebase project variables, and the runtime-only `FIREBASE_SERVICE_ACCOUNT_JSON` secret in Render. `/health` reports process health; `/ready` fails with HTTP 503 when Firestore mode is selected without server configuration.

## Testing

```bash
pnpm run typecheck
pnpm run build
pnpm test
pnpm run lint
pnpm run production-check
```

The unit and integration suite does not require external provider availability. The known Internet Archive regression item is `gov.archives.arc.49737`; live provider checks are bounded and should be run separately from deterministic tests. Metadata availability does not guarantee playable media availability.
